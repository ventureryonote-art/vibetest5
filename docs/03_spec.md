# 要件定義書

> `docs/01_customer.md`（3行＋🔮の仮説）から起こしました。
> 🔮 が付いた項目は、**まだ確かめていない仮説に依存している**という意味です。
> このとおりに `/build` で実装します。

---

## 0. 画面の型

| | 選んだもの | 理由 |
|---|---|---|
| **LAYOUT** | **`queue`** | 3行目が「**今日返信すべき人**が、一目で分かるといい」＝**待たせている人を古い順に片づける**画面。放置日数が主役になる |
| **TONE** | **`pine`** | 1行目の相手が**教育・スクール**（体験授業を入口にした教室）のため |
| **DENSITY** | 🔮 **`normal`** | 🔮 問い合わせは月30〜50名（1日1〜2名）で、未返信が溜まっても一覧は10名前後。`compact` ほど詰める必要がなく、`due`/`roomy` ほど1件が長期でもない<br>→ 確かめ方: 「未返信が一番溜まったとき、何人くらい溜まりますか？」 |
| **UNIT** | **`名`** | 数えているのは書類でも品物でもなく**人（保護者）**。「今日返信すべき"人"」という3行目の言葉に合わせる |

**区分（CATEGORIES）**: `LINE` / `電話` / `HP` / `紹介`

- `LINE` `電話` `HP` は、2行目に本人が書いた**事実**の3経路
- 🔮 `紹介`（在籍保護者・きょうだい経由）を1つ足す。教室業では一定割合あると思われる
  → 確かめ方: 「LINE・電話・HP以外に、問い合わせが来る経路はありますか？」

---

## 1. このツールが解くこと

**今日返信すべき保護者が1画面で分かり、返信漏れ（月2〜3名）がなくなる。**

---

## 2. 使う人と、使う場面

- **使う人**: 🔮 体験授業を入口にしている個人教室のオーナー、または問い合わせ返信を任されている教室長・受付スタッフ（受付専任はおらず、片手間で返信している）
- **いつ開くか**: 🔮 **朝、教室を開ける前の5分。**および、電話を切った直後・LINEに気づいた直後にその場で1名足すとき
  → 確かめ方: 「毎朝、教室を開ける前に必ず見るものは何ですか？」
- **開いて最初にしたいこと**: **一番長く待たせている保護者に、今すぐ連絡する。**そのために、未返信の人だけが古い順に並んでいてほしい

---

## 3. 画面（テンプレートの3画面をそのまま使う）

**一覧 / 新規登録 / 設定** の3画面。ルーティングは増やしません。

### 一覧画面に、上から順に出るもの

1. **数字が3つ**（今の状況）
   `[ 9 ]未返信` ／ `[ 3 ]3日以上 待たせている` ／ `[ 24 ]全24名`
2. **絞り込み**
   `未返信 / 返信済み / 全件` の切り替え、`区分（LINE・電話・HP・紹介）`での絞り込み、**名前・用件メモでの検索**
3. **一覧（未返信を、待たせている順に）**
   見出しは `未返信（待たせている順）　9 名`。1行に出るのは —
   - **保護者名（お子さんの学年）** … 例: 佐藤さん（小5）
   - **用件メモ** … 例: 週2回コースの料金を知りたい
   - **経過日数のバッジ** … 例: `9日`　← **3日以上待たせている行は色が変わる**
   - **区分のバッジ** … 例: `LINE`
   - **問い合わせ日** … 例: 08/12
   - **「返信済みにする」ボタン**

### 新規登録画面

保護者名・区分・問い合わせ日（初期値は今日）・用件メモ を入れて「登録」。

### 設定画面

ツール名の変更と、データの消去。

> ⚠ **画面に出さないもの**: 「やらないこと」「🔮の仮説」「出口の3点」「競合」。これらは社内メモであり、この文書の中で使い切ります。
> **LP（宣伝ページ）は作りません。**キャッチコピー・課題説明・CTAボタンは1つも置きません。

## 4. データ項目

**5項目**（テンプレートの上限ちょうど）。

| 項目 | 型 | 必須 | 例 |
|---|---|---|---|
| 保護者名 | 文字列 | ○ | 佐藤さん（小5） |
| 区分（問い合わせ経路） | LINE / 電話 / HP / 紹介 | ○ | LINE |
| 問い合わせ日 | 日付（YYYY-MM-DD） | ○ | 2026-08-12 |
| 用件メモ | 文字列 | — | 週2回コースの料金を知りたい |
| 返信済みか | true / false | ○ | false |

> 🔮 **電話番号・メールアドレスは持ちません。**返信自体は今まで通り各アプリ（LINE・電話・メール）で行うため、連絡先はそちらに既にあります。項目を5つに収めるのと、個人情報を増やさないのと、両方の理由です。
> → 確かめ方: 「この一覧に電話番号が無いと、返信のとき困りますか？」

## 5. 操作（3つまで）

| # | 操作 | 何が起きるか |
|---|---|---|
| 1 | **登録する** | 新規登録画面で保護者名・区分・日付・用件メモを入れると、未返信の一覧に入る。日付の初期値は今日 |
| 2 | **返信済みにする** | その行が未返信の一覧から消え、上の「未返信」の数が1減る。データは消えず「返信済み」で見返せる（押し間違えたら未返信に戻せる） |
| 3 | **絞り込む・探す** | 「未返信だけ」に切り替える／区分（LINE・電話・HP・紹介）で絞る／名前・用件メモで検索する |

## 6. やらないこと

`CLAUDE.md` 3章の3つ＋今回の範囲外：

- **お客さん側からの申し込みフォームは作らない**（教室側が手で登録する台帳に絞る）
- **LINE・メールとの自動連携、自動返信は作らない**（返信は今まで通り本人が各アプリで行う）
- **入会後の生徒管理（月謝・出欠・成績・請求）は作らない**
- **ログイン・アカウントは作らない**（第3回で扱う）
- **複数人での共有・別端末からの閲覧はしない**（`localStorage` は端末ごと。第3回で扱う）
- **メール送信・通知（リマインド）はしない**
- **AIによる返信文の自動生成はしない**（毎回コストがかかるため、上限設計とセットで別途）

## 7. 完成条件

見れば誰でも Yes / No を判定できる形で3つ。

- [ ] **未返信の保護者が、待たせている日数の長い順に並んで表示され、見出しに「〇 名」と数が出ている。3日以上待たせている行は色が変わっている**
- [ ] **「返信済みにする」を押すと、その人が未返信の一覧から消え、上の「未返信」の数字が1減る**
- [ ] **ブラウザをリロードしても、登録した人と、返信済みにした状態が残っている**

## 8. 保存方法

`localStorage` に1つのキーで保存する。キー名: **`taiken-inquiries`**

- 読み書きは **`useEffect` の中だけ**で行う（サーバー側に `localStorage` が無いため、外で読むとビルドが落ちる）
- 読み込みが終わるまで保存を走らせない（`loaded` フラグを使う）
- **外部のサーバーには一切送らない。**保護者名は個人情報であり、その端末のブラウザの中だけに置く

※ 端末ごとの保存です。複数人での共有は第3回で扱います。

## 9. ダミーデータ

初回表示で寂しくないよう、**架空の見本データを14名**入れる。実在の人名・連絡先は使わない。

- **未返信9名 / 返信済み5名**（どちらのタブにも中身がある状態にする）
- 日付は固定値ではなく `ago(n)`（今日から何日前）で作る。いつ開いても「今の話」に見え、放置日数のバッジが機能する
- `n` は 0〜21 に散らす。**3日以上待たせている人が数名混ざる**ようにして、色が変わることを初回から確認できるようにする
- 用件メモは、教室の人が実際に書きそうな一文にする（例:「折り返し希望 18時以降」「平日夕方のみ。部活が19時まで」）

> 見本データのままのときは、一覧の上に「これは見本です」という案内を出す。1名でも追加・削除すると自動で消える。
